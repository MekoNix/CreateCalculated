# Картинки предметов

Значки предметов на странице это настоящие картинки, как в инвентаре игры. Их собирает инструмент `createcalc-icons` на вашем компьютере. Без них калькулятор тоже работает: вместо картинок страница показывает цветные квадраты с буквами.

## Почему их нет в репозитории

На ассеты Create (`assets/`) действует лицензия All Rights Reserved, код мода открыт по MIT, см. `LICENSE.md` в его репозитории. Текстуры Minecraft принадлежат Mojang. Распространять их нельзя, поэтому в репозитории лежит только инструмент. Картинки и скачанные JAR остаются в папке `data/`, она и файлы `*.jar` указаны в `.gitignore`. Не указывайте для картинок другую папку внутри репозитория.

## Как получить

Если картинок нет, сервер при запуске сам спросит, собрать ли их. Ответ «нет» запоминается в файле `.no-install-prompt` в папке картинок: удалите его, чтобы вопрос появился снова. Без терминала, например в службе, сервер не спрашивает и только напоминает о команде.

Вручную:

```sh
cargo run --release --bin createcalc-icons
```

Этого достаточно: инструмент скачает то, чего нет, и сложит картинки в `data/icons/`. Рецепты из `data/bundle.json` нужны для картинок тегов и отчёта о покрытии, поэтому сначала выполните [импорт](import.md). После нового импорта с другими модами запустите инструмент ещё раз.

Сервер находит папку сам, перезапускать его не нужно. Откройте страницу заново.

### Аддоны

Один аргумент на мод, slug берётся из адреса страницы мода на Modrinth:

```sh
cargo run --release --bin createcalc-icons -- --mod createaddition
```

Версию можно закрепить: `--mod create@6.0.10`. Чтобы мод подключался всегда, допишите его в `DEFAULT_MODS` в `icons/src/main.rs`.

### Свои JAR

Файлы можно указать прямо в команде, тогда они не скачиваются. Поздние файлы заменяют ранние с тем же путём.

```sh
cargo run --release --bin createcalc-icons -- <minecraft.jar> <create.jar> <аддон.jar>
```

Инструмент сам смотрит, что внутри: есть ли текстуры игры и какие моды указаны в `neoforge.mods.toml`. С `--no-download` он работает только с указанными файлами.

| Файл | Где искать (Modrinth App) |
|---|---|
| Minecraft | `meta/versions/1.21.1-<neoforge>/1.21.1-<neoforge>.jar`, текстуры там есть |
| Create и аддоны | `profiles/<профиль>/mods/` |

NeoForge не нужен: ни Create, ни Crafts & Additions не берут из него моделей.

### Параметры

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--mod SLUG[@ВЕРСИЯ]` | | Ещё один проект с Modrinth, можно повторять |
| `--minecraft ВЕРСИЯ` | `1.21.1` | Версия игры |
| `--loader ИМЯ` | `neoforge` | Загрузчик модов на Modrinth |
| `-o`, `--out ПАПКА` | `data/icons` | Куда писать картинки |
| `--bundle ФАЙЛ` | `data/bundle.json` | Рецепты для тегов и отчёта |
| `--size N` | `128` | Размер картинки в пикселях |
| `--jars ПАПКА` | `data/jars` | Куда скачивать JAR |
| `--update` | | Спросить у Modrinth новую версию, даже если файл уже скачан |
| `--no-download` | | Ничего не скачивать |

## Откуда берутся данные

| Что | Откуда | Чем проверяется |
|---|---|---|
| Minecraft | `client.jar` по манифесту Mojang (`piston-meta.mojang.com`) | sha1 из манифеста |
| Create, аддоны | Modrinth API, `/v2/project/<slug>/version`, новейший релиз под версию игры и загрузчик | sha1 и sha512 из ответа |

Файл с неверным хешем удаляется, и инструмент останавливается. Уже скачанные файлы записаны в `data/jars/downloads.json` и при каждом запуске сверяются с записанными хешами, поэтому повторный запуск не ходит в сеть и не меняет версию мода сам по себе. Скачанные JAR это только данные: инструмент читает из них файлы как из архива и ничего не запускает.

## Как получается картинка

- **Плоские предметы** (`item/generated`): слои `layer0`, `layer1` и так далее накладываются друг на друга, каждый пиксель текстуры становится квадратом.
- **Блоки и модели**: цепочка `parent`, переменные `#x`, `elements` с `from`, `to`, `faces`, `uv`, `rotation`, поворот элементов с `rescale`, трансформация `display.gui`, ортографическая проекция, отсечение задних граней, буфер глубины. Освещение повторяет игру: те же два источника и формула шейдера, поэтому верх яркий, левая грань темнее, правая ещё темнее. На иконках с вики яркости совпали с точностью до нескольких единиц.
- **Модели NeoForge**: `neoforge:obj` (дробильное колесо, водяное колесо, маховик и другие) и `neoforge:composite`.
- **Анимированные текстуры**: первый кадр по файлу `.mcmeta`.
- **Прозрачность**: пиксели с прозрачностью ниже 0.1 отбрасываются, как в игре, полупрозрачные смешиваются от дальних к ближним.
- **Предметы, которые игра рисует кодом** (`builtin/entity`): у сундуков, кроватей, знамён, щита, ящика шалкера, проводника, горшка и голов нет модели в файлах. Размеры их коробок перенесены в `icons/src/entity.rs`, текстуры берутся из ваших JAR. Для остальных (голова дракона, голова пиглина) картинки нет, страница покажет буквы.
- **Инструменты Create со своим рендером**: у картофельной пушки, жезла симметрии и миростроителя вместе с основной моделью рисуются их части при неподвижном положении. У Extendo Grip нет выдвижной руки, она задаётся анимацией в коде мода.
- **Цвета из кода игры** (`icons/src/tint.rs`): трава, листва, кувшинка, кожаная броня, зелья, вода, знамёна. Зелья показаны с цветом по умолчанию, жидкости-зелья с цветом своего эффекта. Яйца призыва остаются серыми: их цвета записаны в коде игры по одному на моба, в рецептах они не встречаются.
- **Жидкости**: первый кадр текстуры `<имя>_still` на весь квадрат, как в книгах рецептов. Если у жидкости нет текстуры под её пространством имён, берётся жидкость с тем же именем из другого мода. Так молоко игры получает картинку из Create.
- **Теги**: первый участник тега, у которого есть картинка.

Модели из `models/item/` без предмета (`template_*`, `generated`) и варианты брони с отделкой (`*_trim`, их текстуры игра создаёт при запуске) пропускаются либо попадают в список без картинки, на страницу они не выводятся.

## Покрытие

На Minecraft 1.21.1, Create 6.0.10 и Crafts & Additions 1.6.0:

| Что использует `data/bundle.json` | Всего | С картинкой |
|---|---|---|
| Предметы | 1648 | 1648 |
| Жидкости | 8 | 8 |
| Теги | 193 | 192 |

Без картинки остаётся `#minecraft:convertable_to_mud`: такого тега предметов в игре нет, есть только тег блоков. Всего создаётся 2249 картинок, около 6 МБ.

## Что читает страница

`data/icons/index.json`:

```json
{
  "version": "3f2a9c01d4e8b702",
  "size": 128,
  "icons": {
    "create:cogwheel": "items/create/cogwheel.png",
    "fluid:minecraft:water": "fluids/minecraft/water.png",
    "#c:ingots/iron": "items/minecraft/iron_ingot.png"
  }
}
```

Сервер отдаёт папку по адресу `GET /api/icons/...`, см. [API](api.md). Страница один раз читает индекс и больше не спрашивает, есть ли картинка. Для машин берутся значки их блоков, у ручной работы остаются буквы. `version` меняется вместе с картинками и входит в их адрес, так что браузер может хранить их долго и всё равно увидит новые после нового запуска инструмента.

Старые файлы инструмент не удаляет: они просто не попадают в индекс. Для чистой сборки удалите `data/icons` перед запуском.
