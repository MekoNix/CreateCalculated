# Как работает расчёт

Это не поиск по дереву. Скорость задаёт пользователь, а решатель ищет самый дешёвый способ её получить. Дерево не подходит, потому что рецепты образуют циклы и побочные выходы одних служат входами других. Расчёт сводится к линейной задаче (`core/src/plan.rs`).

## Шаги

1. **Сбор.** От целей идём назад и собираем нужные рецепты и ресурсы. На складе и на базовом сырье обход останавливается.
2. **Уравнения.** Для каждого ресурса: `произведено + добыто = потрачено + остаток + заказано`.
3. **Минимизация** стоимости (таблица ниже).
4. **Машины.** По числу запусков рецепта в минуту и формулам из [formulas.md](formulas.md) считаются машины, SU и бёрнеры.
5. **Граф.** Запущенные рецепты становятся узлами машин. Добыча, склад, остатки и цели становятся отдельными узлами. Теги сворачиваются: на рёбрах всегда настоящий предмет.

## Стоимость

| Что | Цена | Зачем |
|---|---|---|
| Сырьё из `core/data/base_resources.txt` | 1 за предмет | То, что обычно добывают |
| Очищенное бревно | 1,5 | Обычное выгоднее, если рецепт принимает оба |
| Жидкость из списка | 0,001 за mB | Вода и лава почти бесплатны |
| Прочее сырьё без рецепта | 1000, с предупреждением | Только если другого пути нет |
| Запуск рецепта | 0,01 за каждый произведённый предмет | Цепочки без пользы и сборка блока ради разборки невыгодны |
| Остаток | 0 | Лишнее становится конечным узлом. Любая цена заставляет решатель строить машины для уничтожения или прессовки остатков |
| Сжатая форма (блок при наличии обратного рецепта) | сумма частей + 1% | Блок нельзя добыть дешевле его содержимого, и при ничьей берутся части |
| Склад | 0 | Выбирает пользователь |

Предмет с рецептом нельзя просто взять: блок появится в решении, только если его сделали из сырья. Обратные пути остаются вариантами на узле, их можно выбрать вручную. Склад работает так же: если блок железа у вас есть, отметьте его как `stock`.

Числа подобраны по результатам на настоящих рецептах, это эвристика.

## Режим полной автоматизации

Поле `mode: "full_auto"`. Цены меняются так, чтобы решатель сначала шёл через бесконечные источники:

| Источник | Цена | Узел |
|---|---|---|
| Генератор: булыжник, камень, вода, лава | 0,01 (жидкости 0,00001 за mB) | `generate`, для камня с дрелями |
| Ферма: `core/data/farm_resources.txt` | 5 | `gather` |
| Добыча: `core/data/mined_resources.txt` | 100, попадает в `manual` | `gather` |
| Прочее без рецепта | 1000, попадает в `manual` | `gather` |

Обход не останавливается на добываемых ресурсах, поэтому гравий получается из булыжника, а железо промывкой гравия. Что вывести нельзя (медь, цинк, редстоун, уголь), остаётся ручной добычей и перечисляется в `manual`.

## Выбор машины

Для обычных крафтовых рецептов по умолчанию берётся машина с наименьшей нагрузкой при заданном RPM: крафтер, миксер (бесформенные рецепты) или пресс (полные квадраты 2×2 и 3×3 из одного предмета). Для остальных рецептов машина первая в списке, например вентилятор для плавки. Выбор на узле важнее значения по умолчанию.

## Известные ограничения

- Число машин не влияет на выбор рецепта, только количество сырья.
- Какого именно члена тега брать (дуб или акация), решает решатель, при равной цене выбор произвольный. Переключателя пока нет.
- Логистика не считается: лента, воронки и насосы не ограничивают поток.
- Простой машин между операциями (ожидание предмета, сканирование) не учитывается.
- Аддоны пока не подключены: типы рецептов и машины заданы в коде, рецепты неизвестных типов импорт пропускает и показывает в статистике.
