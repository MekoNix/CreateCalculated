# Импорт рецептов

Рецепты лежат в `data/bundle.json`, эта папка не попадает в git.

## Обычный способ

Запустите сервер: если файла нет, он спросит, скачать ли всё нужное. То же вручную:

```sh
cargo run --release --bin createcalc-recipes
cargo run --release --bin createcalc-recipes -- --mod createaddition
```

Скачивается Minecraft от Mojang, NeoForge из его репозитория Maven, Create и указанные моды с Modrinth, с проверкой контрольных сумм. Файлы хранятся в `data/jars/` и только читаются как архивы. Без `--update` повторный запуск обходится без сети. Без терминала сервер ничего не спрашивает и останавливается с подсказкой.

## Из своих файлов

```sh
cargo run --release --bin createcalc-import -- -o data/bundle.json <minecraft.jar> <neoforge-universal.jar> <create.jar>
```

Порядок важен: сначала игра, потом NeoForge, потом моды. Поздние файлы заменяют рецепты с тем же id и дополняют теги.

| Файл | Где искать (Modrinth App) |
|---|---|
| Minecraft | `meta/versions/1.21.1-<neoforge>/1.21.1-<neoforge>.jar` |
| NeoForge | `meta/libraries/net/neoforged/neoforge/<версия>/neoforge-<версия>-universal.jar` |
| Create | `profiles/<профиль>/mods/create-1.21.1-6.0.10.jar` |

Команда выводит статистику: сколько рецептов загружено, сколько отброшено по условиям (например, нужен другой мод), какие типы пропущены и что не разобралось. На Create 6.0.10 получается около 2600 рецептов без ошибок разбора.

Пропускаются спецрецепты без постоянного результата (покраска брони, копирование книг) и готовка на костре.

Значки предметов собираются отдельно и из тех же JAR, см. [картинки предметов](icons.md). Это шаг необязательный, но запускать его лучше после импорта: инструмент берёт из `data/bundle.json` состав тегов.
